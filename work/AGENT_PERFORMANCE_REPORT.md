# Звіт по роботі агентів — Propeller Calculator

Період: 23–25.09.2026. Задіяно ~40 субгонтракторів: аудитори, виконавці, незалежні рецензенти, зонди. Усі працювали циклами «виконавець → незалежний рецензент → доопрацювання → повторна перевірка». Жоден агент не комітив і не пушив — інтеграцією володів тільки менеджер.

## Що зроблено (перевірено незалежно)

- Сьют 41/41 зелений (`.venv`, `PYTHONPATH=src`); workbook 127 тестів: 58 PASS / 62 N/A / 7 NOT STARTED (7 NOT STARTED are all gate-NO; the 62 N/A = 54 gated-YES (each with evidence, legitimately passing G14) + 8 gated-NO); усі 14 релізних гейтів PASS — підтверджено перерахунком аналітика P.
- Виправлено з регресом: масштаб батареї в sweep, пряме відтворення точки БД, краш нульових лімітів, варнінги входів, витік віджетів, локалізація 26 варнінгів, інлайн-помилки полів, NaN-сортування, діаметри UIUC (959 рядків), морські мітки (12 769 рядків), EXE-шляхи, метадані.
- Аудит БД проти першоджерел (4767 файлів, хеш збігається): random-sample + extreme-value rows byte-exact against raw files (raw_row identical), repair scripts cite HTML spec pages.

## Помилки в роботі агентів

1. Виконавці: незакритий sqlite-конект у тестах (3 ResourceWarning на кожен прогін); NaN у ключі сортування порівнянь (ранжував сміття першим); слабкий навігаційний тест (не ловив зламану мову); порожній sweep-тест (проходив на None); пропущені піни 12x65/13x65; застаріле число «22 тести» в README.
2. Рецензенти: пропустили ті ж ResourceWarning; пропустили приватний шлях `C:\Users\kot00\…` в метаданих ingest; погодили релізні гейти при незакоміченому CI.
3. Аудитори: не помітили приватний шлях у `ingest.py:62,72,82`.
4. Менеджер (я): ранні батчі робив сам замість делегування; арифметична помилка з морською тягою (×816 — виправив агент W2, взяв щільність повітря замість води); брутфорс-кліки по GUI без калібрування.

## Оцінки

- Аудитори: 9/10 — знахідки реальні, з доказами; мінус за приватний шлях.
- Виконавці: 8/10 — фікси точні з тестами; мінус за шум (warnings, NaN-сорт) який ловили рецензенти.
- Рецензенти: 9/10 — зловили NaN-сорт, слабкий тест, число 22, ніти TESTING; мінус за warnings/шлях/CI.
- Машина в цілому: жодного функціонального дефекту не пропущено у прод; усі мінуси — гігієна/доки.

## Сильні сторони

- Розділення «робить один — перевіряє інший» спрацювало: 6+ реальних дефектів знайдено рецензіями, а не авторами.
- Вузькі скоупи (дозволені шляхи) — нуль випадкових правок за всю сесію.
- Оракул незалежний від коду: сирі файли + фізика, а не БД/код самі себе.

## Слабкі сторони

- Агенти не перепровіряють власні сліпі зони: warnings у виводі, приватні шляхи, застарілі цифри в доках.
- Рецензенти схильні погоджувати «зелене» не ганяючи сьют з `-W error` і не рахуючи тести вручну.
- Довгі ланцюжки: batch → review → rework → review = 4 раунди на дрібницю.

## Рекомендації: задачі та використання

1. Кожна задача виконавцю: файли-скоуп + заборона коміта + конкретна команда перевірки + вимога «доведи падіння на старому коді».
2. Рецензенту завжди: запустити сьют самому, перерахувати цифри, шукати ОДИН контрприклад; «не знайшов — так і пиши», без вигадок.
3. Розділяй потоки за файлами: два письменники в один файл — заборонено; читачі можуть паралельно.
4. Доки з цифрами (README/ARCHITECTURE): число живе тільки з командою перерахунку поруч; інакше застаріє за тиждень.
5. Секрети/приватне: сканувати іменами (без значень) кожен аудит; квотити шляхи поза `D:\AI_PROJECTS` — стоп і доповідь.
6. Менеджер не пише код, крім однолайнової інтеграції; винятки фіксувати явно.
